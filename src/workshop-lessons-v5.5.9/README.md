# Проверка уроков мастерской

`lessons.json` — окончательные абзацы трёх уроков; в языковых файлах книги они разделены на страницы. При обновлении меняются только описания, без новых ID, задач, наград и зависимостей.

`WaterMixerProbe.java` — исходник отдельного клиентского проверочного мода для Minecraft 1.21.1, NeoForge и Create 6.0.10. Он не входит в Packwiz-манифест и не устанавливается игрокам. Для сборки нужны соответствующие API Minecraft/NeoForge/Create и вложенные зависимости Create. Это исходник использованного стенда, а не готовый автономный тестовый пакет.

Мод активируется только в профиле `ZombKotom-Quest-QA` с файлом `minecraft/water-mixer-qa.enabled`. Он очищает ограниченную площадку тестового мира, ставит блоки, подаёт исходные ингредиенты и проверяет результат обычных тиков игры. Использовать только отдельный одноразовый мир: стенд меняет блоки и время суток, отменяет два достижения тестового игрока и закрывает клиент после записи отчёта.

Структура привода при ручном повторе (координаты можно целиком сместить):

| Блок | Координаты | Ориентация |
| --- | --- | --- |
| Малое водяное колесо | 192, 67, 192 | Ось X, поток вниз с северной стороны |
| Большая шестерня | 193, 67, 192 | X |
| Малая шестерня | 193, 68, 193 | X |
| Большая шестерня | 194, 68, 193 | X |
| Малая шестерня | 194, 69, 194 | X |
| Редуктор | 195, 69, 194 | Ось корпуса Z, соединяет X и Y |
| Вал | 195, 68, 194 | Y |
| Малая шестерня | 195, 67, 194 | Y |
| Миксер | 196, 67, 194 | Шестерня зацеплена с предыдущей |
| Чаша | 196, 65, 194 | Один блок воздуха до миксера |

Подайте 8 андезита и 8 железных самородков, заберите 8 сплава. Перекройте воду и дождитесь остановки. Положите ещё по одному ингредиенту: без вращения обработки быть не должно. Восстановите поток и получите девятый сплав. Не подключайте дополнительные станки при проверке указанного баланса нагрузки.

Проверены обычные 8/16/32 об/мин, 256 SU источника, 128 SU миксера и естественная выдача достижений. Настроенный порог MEDIUM равен 30 об/мин; 32 — пример достижимой скорости через шестерни, а не точное значение порога.

В первую попытку стенд использовал `HORIZONTAL_FACING` вместо шестинаправленного `FACING` водяного колеса. После исправления стенда повтор прошёл. Результат не подтверждает полный маршрут выживания, сборку деталей из добытых ресурсов, автоматическую подачу или сетевую игру. Границы проверки также описаны в [отчёте выпуска](../../UPDATE-5.5.9-RU.md).
